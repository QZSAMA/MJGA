# MJGA 安全文本链路基线设计

## 1. 背景与目标

MJGA 已在 `dev` 分支实现 J2ME 文本聊天客户端，以及 Go、Python 两套 OpenAI 兼容代理。当前实现能够表达完整链路，但仍有硬编码凭证、无客户端认证、无请求边界、UTF-8 解码错误、JSON 转义处理不完整和构建不可复现等问题。

本轮目标是建立一个可安全部署、可自动验证的文本聊天基线：W995 客户端能够通过受控 HTTP 网络调用代理，代理经过认证后访问 HTTPS 上游，并在有限内存和异常网络条件下返回可理解的结果。

## 2. 范围

### 2.1 本轮包含

- 从代码和调试配置中移除硬编码上游 API Key。
- 使用 `X-MJGA-Token` 对 J2ME 到代理的请求进行共享设备令牌认证。
- 为 Go 与 Python 代理统一启动配置、认证、请求限制、超时、错误响应和日志策略。
- 修复 J2ME 请求与响应的 UTF-8 编解码、JSON 字符串转义解析、响应大小和历史数量边界。
- 修复 Ant/JAD、MicroEmulator 脚本和 Go Docker 构建中的已知一致性问题。
- 为代理契约、J2ME JSON 处理和构建增加自动化测试。
- 更新 README、部署说明和路线图，使其与实际实现一致。

### 2.2 本轮不包含

- 语音合成、音频播放、图片生成或图片显示。
- 流式响应。
- 会话持久化、跨启动历史恢复或完整会话管理。
- 多用户账户、OAuth、管理后台或数据库。
- 对已公开 Git 历史执行破坏性重写。已暴露的 API Key 必须在服务提供商侧撤销并轮换。
- 宣称完成 W995 真机验收；真机测试仍是完成本基线后的独立里程碑。

## 3. 架构决策

### 3.1 兼容现有协议

保留 `POST /v1/chat/completions` 和 OpenAI 兼容的请求、成功响应结构，避免在安全修复阶段同时引入新业务协议。客户端继续发送 `model` 和单条 `user` message，代理仅转发到配置的固定上游地址。

### 3.2 双代理行为一致

Go 版本作为生产部署候选，Python 版本用于开发调试。两者必须共享同一份外部契约：

| 行为 | 约定 |
|---|---|
| 健康检查 | `GET /ping` 不要求认证，返回 `200` |
| 聊天接口 | `POST /v1/chat/completions` |
| 客户端认证 | 请求头 `X-MJGA-Token` |
| 缺失或错误令牌 | `401`，统一 JSON 错误 |
| 非 JSON 或结构无效 | `400`，统一 JSON 错误 |
| 请求过大 | `413`，统一 JSON 错误 |
| 频率超限 | `429`，统一 JSON 错误 |
| 上游超时 | `504`，统一 JSON 错误 |
| 上游网络失败 | `502`，统一 JSON 错误 |
| 上游响应过大 | `502`，统一 JSON 错误 |
| 上游非 2xx | 保留上游状态码，但返回大小受限的上游响应 |

统一错误格式为：

```json
{
  "error": {
    "code": "unauthorized",
    "message": "client token is invalid"
  }
}
```

### 3.3 配置与凭证

代理启动时读取：

| 环境变量 | 必填 | 默认值 |
|---|---:|---|
| `API_KEY` | 是 | 无 |
| `CLIENT_TOKEN` | 是 | 无 |
| `API_URL` | 否 | 当前火山方舟 OpenAI 兼容地址 |
| `PORT` | 否 | `8080` |
| `UPSTREAM_TIMEOUT_SECONDS` | 否 | `60` |
| `MAX_REQUEST_BYTES` | 否 | `8192` |
| `MAX_RESPONSE_BYTES` | 否 | `32768` |
| `RATE_LIMIT_PER_MINUTE` | 否 | `10` |

`API_KEY` 或 `CLIENT_TOKEN` 缺失时，服务必须拒绝启动。客户端令牌使用常量时间比较。当前基线使用一个共享设备令牌；未来支持多设备时再引入每设备令牌存储。本轮明确要求代理只能部署在家庭内网、VPN 或受控隧道中，因为 W995 到代理仍使用明文 HTTP。

限流采用进程内、全局固定窗口计数器，每分钟最多接受 `RATE_LIMIT_PER_MINUTE` 个已认证聊天请求。进程重启会重置计数；这满足单设备家庭部署基线，多实例或多设备部署不在本轮范围内。

J2ME 的 `api.url`、`client.token` 和 `model` 从未提交的 `config.properties` 注入 JAD/Manifest 自定义属性。仓库只提供无秘密的 `config.properties.example`。MIDlet 使用 `getAppProperty()` 读取配置；必填值缺失时在 UI 中显示配置错误，不发起网络请求。

## 4. 请求数据流

1. 用户在 W995 的 `TextField` 输入不超过 500 个字符的问题。
2. MIDlet 从应用属性读取 API URL、客户端令牌和模型名称。
3. `JsonParser` 对用户内容进行 JSON 转义，并使用 UTF-8 字节发送请求。
4. `HttpClient` 添加 `Content-Type: application/json; charset=utf-8` 和 `X-MJGA-Token`。
5. 代理先校验令牌，再执行限流、请求大小和 JSON 结构检查。
6. 代理使用固定 `API_URL` 和服务端 `API_KEY` 调用上游；用户不能覆盖目标地址或 Authorization。
7. 代理限制上游响应大小，并将允许的状态和响应返回客户端。
8. 客户端按 UTF-8 解码有限长度的响应。成功时解析第一个 `choices[0].message.content`；失败时展示简短错误，不保存完整失败响应。
9. UI 更新统一通过 `Display.callSerially()` 执行。

## 5. J2ME 内存与兼容策略

- 单次代理请求上限默认 8 KiB，单次代理和客户端响应上限默认 32 KiB。
- 客户端使用固定大小字节缓冲区读取，不逐字节转为 `char`。
- 客户端只保留最近 10 组问答；超出时删除最早记录。
- JSON 字符串扫描器支持 `\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t` 和 `\uXXXX`，不使用正则表达式。
- HTTP 状态码在解析正文前检查；网络异常、认证失败、限流和上游失败显示不同的短错误。
- 保持 MIDP 2.0/CLDC 1.1 API 边界，不引入大型第三方库。
- 主机 `javac` 编译仅作为快速静态检查。真正 W995 发布构建仍必须经过 Java ME WTK/SDK 预校验和真机安装测试，文档不得把普通 JDK 编译描述为真机兼容证明。

## 6. 构建设计

### 6.1 J2ME

- Ant 是唯一正式构建入口；删除当前不参与打包、且与 Ant 表达不同依赖来源的 Gradle/Maven 文件，避免三个构建入口表达不同语义。
- `resources` target 在 `res/` 不存在时不失败。
- JAD 自动写入实际 `MIDlet-Jar-Size`。
- JAD/Manifest 声明 HTTP 联网权限和 `MJGA-Api-Url`、`MJGA-Client-Token`、`MJGA-Model`。
- `run-emulator.sh` 只引用仓库中实际存在的 JAR，并在产物不存在时给出明确提示。
- 增加 `run-emulator.ps1`，提供与 shell 脚本等价的 Windows 模拟器启动入口。

### 6.2 Go 代理

- 提交与 `go.mod` 一致的 `go.sum`。
- Dockerfile 只复制实际存在的依赖文件并执行可复现构建。
- 删除仓库根部已提交的 21 MB 代理二进制，发布二进制改由 Release 或 CI 产出。

### 6.3 Python 代理

- 保留 `uv.lock`。
- 在 `pyproject.toml` 增加测试依赖与测试命令说明。
- 使用应用工厂或显式配置对象，使测试不依赖真实环境变量和真实上游。

## 7. 测试策略

所有行为修复遵循测试先行：先写一个能证明缺陷的失败测试，再做最小实现。

### 7.1 代理契约测试

Go 和 Python 各自覆盖：

- `/ping` 可用。
- 缺少、错误和正确 `X-MJGA-Token`。
- 请求体超过限制。
- 非法 JSON 和缺少 `messages`。
- 正常上游成功响应。
- 上游非 2xx 透传。
- 上游超时、连接失败和响应过大。
- 频率限制达到阈值后返回 `429`。
- 日志不包含 API Key、客户端令牌和完整用户正文。

上游调用全部使用本地 `httptest` 或 HTTPX mock transport，不访问真实模型服务。

### 7.2 J2ME 测试

- 请求 JSON 对引号、反斜杠、换行和中文正确编码。
- 响应解析支持所有约定转义和 `\uXXXX`。
- 被截断或格式错误的响应返回解析失败。
- UTF-8 中文响应能够完整还原。
- 超过响应上限时停止读取并返回明确错误。
- 历史记录超过 10 组时移除最早项。

核心纯 Java 测试通过 Ant 在主机 JVM 执行；设备相关网络和 UI 行为在 MicroEmulator 验证。

### 7.3 构建验证

- Python：静态编译与 `pytest`。
- Go：`go test ./...`、`go vet ./...` 和 Docker build。
- J2ME：Ant 单元测试、打包、JAD 字段检查和 MicroEmulator 启动冒烟测试。
- 最终仍保留 W995 真机安装、联网、中文显示和弱网测试清单。

## 9. 验收标准

本轮完成需要同时满足：

1. 当前分支和工作树中不存在硬编码真实 API Key。
2. 两个代理缺失必填凭证时拒绝启动，认证和限制行为一致。
3. 自动测试能够在不访问真实上游的情况下覆盖成功和主要失败路径。
4. J2ME 能正确处理含中文、引号、反斜杠、换行和 Unicode 转义的回复。
5. 构建产物包含正确 JAD 大小、联网权限和本地注入配置。
6. Go Docker build 不再引用缺失文件；Python 测试和启动路径可复现。
7. 功能分支的不可编译双击实现不合入本基线；菜单折叠功能保持可用。
8. README 和路线图与代码及验证证据一致。
9. 报告明确列出尚未完成的 W995 真机验收，不作超出证据的完成声明。
